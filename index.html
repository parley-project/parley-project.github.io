Java libraries for internet protocols

Parley speaks the protocols.Parlez-vous SMTP ?

parley, from the French parler, "to speak"

A framework for building clients and servers for line-based and binary protocols, plus ready-to-use implementations of FTP, SSH, SFTP, SMTP, IMAP, POP3 and DNS. Files can live anywhere: on disk, in memory, on an FTP or SFTP server, or in a database.

Modules

Take only the layers you need

Every module is a separate Maven artifact. The protocols sit on a small foundation, and anything that stores files does it through parley-files, so an FTP or SFTP server can serve a database as easily as a disk.

parley-files

One file API for every place files live

FileSource looks very much like java.io.File, but many file systems can be used side by side, and a java.nio.file provider covers all of them. Implementations are found at runtime through ServiceLoader, so adding one is a matter of putting a jar on the class path.

Local, memory
Built into parley-files
FTP, FTPS
parley-files-ftp, using the parley-ftp client
SFTP
parley-files-sftp, with JSch, Apache MINA SSHD or parley-ssh chosen at run time
Database
parley-files-jdbc keeps a whole file system in tables
Secrets
parley-credentials-keychain reads passwords from the macOS Keychain, Linux Secret Service or Windows Credential Manager
Java
FileSourceFactory factory = FileSourceFactory.getDefaultFactory();   // local files

FileSource dir = factory.createFileSource("/tmp/example");
dir.mkdirs();

FileSource file = dir.getChild("hello.txt");
try (OutputStream out = file.getOutputStream()) {
    out.write("Hello, FileSource".getBytes(StandardCharsets.UTF_8));
}

for (FileSource f : dir.listFiles()) {
    System.out.println(f.getName() + "  " + f.length() + " bytes");
}

Debugging protocols

Protocols for tools, too

parley-dap

The Debug Adapter Protocol, both ends. Write an adapter that VS Code, Eclipse, vim and other DAP clients can drive, or a client that drives one. Messages are typed classes generated from the official schema, and connections run over sockets, stdin and stdout, or parley-net's non-blocking channels. No dependencies outside Parley.

github.com/parley-project/parley-dap

parley-loupe

Loupe is a debugging protocol designed as an alternative to DAP: JSON messages with stop snapshots, typed values, stable object ids and version negotiation. A bridge lets VS Code and any other DAP client debug a Loupe target.

github.com/parley-project/parley-loupe

Get started

Import the BOM, then add what you need

The bill of materials lists versions of every module that work together, so you never pick versions one by one.

pom.xml · import the BOM
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>us.bringardner.parley</groupId>
      <artifactId>parley-bom</artifactId>
      <version>1.0.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
pom.xml · add modules, no versions
<dependencies>
  <dependency>
    <groupId>us.bringardner.parley</groupId>
    <artifactId>parley-smtp</artifactId>
  </dependency>
  <dependency>
    <groupId>us.bringardner.parley</groupId>
    <artifactId>parley-imap</artifactId>
  </dependency>
</dependencies>
